**验证目标**：本次独立判定的外部行为；不同关键输入/预期路径分别成例。
关联 FLOW/BRANCH/RISK/EVIDENCE/GAP ID；简述本用例要区分的结果，不复制完整风险机理。
**前置条件**：仅列环境、权限、接口和可用夹具；实例状态统一在步骤 0 定义。
**操作步骤**：
若对象是依赖齐备、能独立执行的公开 C 库接口，本栏用一个完整的 `c` 代码块代替下列编号列表。代码包含实际实现的 include、main、明确初始化、按序调用、逐步打印预期/实际值与比较、最后清理；注释标明步骤 0 和后续步骤。所有断言累计到退出码。代码是本例唯一执行步骤和数值 Oracle，正文只解释测试目标与依据，不再另写一套数值、可选调用或末态。完整要求见 references/executable-case-review.md。

其他对象使用其受支持的业务操作：
0. 初始化：明确如何创建本例实例，以及影响后续返回值和断言的初始状态。需要全零时明确实际置零方法；已有实例说明可验证的初态来源。初态只有这一处，不在前置或步骤 1 另设一套。
1. 准备：支持的外部/公开库接口、协议、配置或故障注入动作，写出输入、本步返回及操作后状态。
2. 主要触发：输入、本步返回、操作后变化与保留状态。
3. 按需继续编号记录观测和清理。每次调用按顺序执行；循环明确每轮包含哪些准备和触发，不能把首轮状态用于所有轮次。
**预期结果**：有执行代码时引用其中对应步骤的比较并解释业务含义；否则引用具体步骤号给出返回值、变化与保留状态，分别说明主触发后、验证结束后和清理结束后的状态。明确契约与实现推演的依据；不拿一次运行输出反填期待值。
**观测方式**：独立的抓包、日志、告警、统计或后续行为。
**清理或恢复**：引用编号清理步骤及其末态；无需额外清理时说明当前保留状态和实例如何结束。不要另写一套可选调用。
