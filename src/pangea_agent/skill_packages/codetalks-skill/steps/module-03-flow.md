# 阶段 03：按流程完成分析

读取 references/path-and-case-design.md，按统一的业务路径粒度、耦合关系和独立用例原则执行。

每个流程连续完成源码理解 → 分支/场景推导 → 候选反证 → 风险/SFMEA → 测试设计，再切换下一个流程。不再把全部流程拆成四轮跨步骤写作。

使用 `templates/模块流程模板.md` 作为可裁剪提示，在 `活文档/流程讲解/流程-<FLOW-ID>-<名称>.md` 集中维护：
外部触发与运行时接线、真实主干、重要分支进入条件、状态、资源、数值、并发、异常传播及源码证据。
按复杂度组织正文，不要求固定章节和字数。不适用维度一句说明；复杂的状态机、资源不变量、回绕、竞态和清理路径必须展开，不能因为取消篇幅检查而省略。
每个分支说明外部可构造条件 → 内部判断/保护 → 外部结果，证据使用 repo_id:path:line，区分推导与实际运行。

读取 `references/scenario-expansion-engine.md` 推导适用维度，及 `references/worker-judge-protocol.md` 的候选裁决部分。
候选判断保留完整契约、支持范围、实际传播、保护条件、最小反事实和根因归并。排除、范围限制、补测、合并和待确认保留在分析台账；只有当前实现风险进入风险文档。

`活文档/风险点与SFMEA.md` 是风险唯一主版本：每项保留 risk_id、Flow/Branch/Evidence ID、触发条件、失效模式/原因、局部及系统后果、严重性理由、外部暴露、排除条件和用例 ID。SFMEA 不再另起一套编号或复制源码段落。
`活文档/黑盒测试用例.md` 是用例唯一主版本，使用 `templates/模块用例模板.md`；步骤外部可执行，独立观测和 Oracle 明确，并含清理恢复。内部符号只作追溯，不作为操作。风险至少关联一条用例；不可达例外需真实源码依据，正常/边界/补测用例可不关联风险。没有正式风险时如实说明，不凑风险或用例数。

每完成一个流程或形成可用的部分成果：
1. 更新该流程正文、关联风险/用例和同一份分析台账；不重新生成其他流程。
2. 保存运行计划中的当前流程、已确认分支、待查证据、下一步和待复核 ID。
3. 用 progress 报告真实完成数/总数和当前 FLOW；受阻、未决不计为已分析。
4. 更新并 publish-stage 工作台投影。投影是索引与显示摘要，引用正文、稳定 ID 和证据，不成为第二份分析结论。

compact 前保存上述游标并 handoff。恢复先读状态、计划、台账和当前流程，只复查中断的分析中项，不从头重做。

发布业务流程时读取 references/business-flow-projection.md，维护 mainline_steps 和 branches，供专用阅读器展示主干及分支。
