# 阶段 02：模块盘点

读取 references/path-and-case-design.md，按统一的业务路径粒度、耦合关系和独立用例原则执行。

先做广度盘点，再深入少数高风险流程。写 `活文档/模块盘点.md`，关联稳定的 ENTRY/FLOW/BRANCH/STATE/RESOURCE ID：
- 外部入口及运行时接线、调用者和关键配置。
- 主干流程与重要分支（包括正常和异常路径），模块边界及跨模块依赖。
- 状态转换、资源所有权与生命周期、关键数值和并发角色。
- 待确认入口、无法读取的实现及范围限制。

只在 `活文档/分析台账.md` 维护分析覆盖与处置：项目 ID、流程 ID、适用维度、状态、证据/正文链接、关联风险/用例 ID、缺口和下一步。
状态包括待分析、分析中、已分析、受阻、未决、不适用；不适用写一句有依据的原因，不能把未读内容写成已分析。无需另建七份覆盖门禁。
在运行计划记录流程队列、当前 FLOW/BRANCH 和下一条读取位置。优先级决定顺序，不允许无声省略低优先级流程。
有阶段成果即发布投影（五个数组，未生成项用空数组），可在本阶段尚未完成时发布。禁止用数量代表分析质量。
