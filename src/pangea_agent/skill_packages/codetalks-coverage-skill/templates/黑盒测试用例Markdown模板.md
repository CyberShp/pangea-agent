## 操作步骤

若对象是依赖齐备、能独立执行的公开 C 库接口，本栏用一个完整的 `c` 代码块代替下列编号列表。代码包含实际实现的 include、main、明确初始化、按序调用、逐步打印预期/实际值与比较、最后清理；注释标明步骤 0 和后续步骤。所有断言累计到退出码。代码是本例唯一执行步骤和数值 Oracle，正文只解释测试目标与依据，不再另写一套数值、可选调用或末态。完整要求见 references/executable-case-review.md。

其他对象使用其受支持的业务操作：

每个独立输入/预期场景分别成例；下列步骤共同验证一个目标，不能列成多项独立测试的集合。

0. 初始化：明确如何创建本例实例，以及影响后续返回值和断言的初始状态。需要全零时明确实际置零方法；已有实例说明可验证的初态来源。初态只有这一处，不在步骤 1 另设一套。
1. 准备：调用或操作与具体输入；预期返回/响应；操作后需要确认的状态或事件。
2. 主要触发：调用或操作与具体输入；预期返回/响应；操作后需要确认的状态或事件。
3. 观测：查询或检查方式；预期数据、状态或事件。

从步骤 0 开始连续执行到清理；每次准备调用都有自己的预期，查询返回的数据与动作成功码分开。循环明确每轮包含哪些准备和触发，不能把首轮状态用于所有轮次。源码推导放在分析正文，被否定的尝试放在复核记录。

使用有证据支持的测试入口；库接口测试可调用其公开接口并核对返回值。不要把私有函数或直接写内部状态伪装成黑盒操作；若必须依赖白盒夹具，另记夹具条件和适用边界，尚未具备时明确待确认。
