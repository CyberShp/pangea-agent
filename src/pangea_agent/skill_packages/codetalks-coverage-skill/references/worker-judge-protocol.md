# Producer / Judge 协议

## Producer

写完整工件，不在回复中用摘要代替工件。

## 候选裁决

在现有候选池中记录候选 ID、以下推导和处置，不另建生命周期或语义校验脚本：

1. **完整契约**：引用资产 ID/revision、章节及完整约束；一并带上同段允许行为、例外、调用者责任与适用条件。不能只摘取禁止条款。
2. **支持范围**：触发条件是否属于本次约定的线程、中断、平台、调用方式和输入域？超范围的情形作为适用限制；没有证据扩大范围。
3. **实际传播**：按真实参数类型、当前语言规则和源码保护分支，从入口输入推到外部可观察结果。未覆盖只能说明需要补测，不能代替这条失效路径。
4. **反事实**：只修正候选根因、保持其余行为不变，原现象是否还存在？说明最小修改及修改前后的返回值、状态和外部结果。推导与实际执行证据分开记录，不能声称运行了未执行的实验。
5. **根因归并**：是否有另一候选的同一个修正能消除本现象？若有，比较必要条件和传播路径；同一根因保留一个稳定 risk_id，其他表现链接它及各自用例。仅凭相同行号、相似标题或数量不能合并。

处置使用当前实现风险、适用限制、覆盖缺口/补测场景、合并到已有根因、排除、待确认。记录理由和证据；合并条目写明保留的 risk_id。存在合理疑点而证据不足时保留待确认，不能强升为已证实缺陷。

资产读取遵守当前 Run 的冻结 manifest。覆盖率阶段 01–04 允许回查冻结材料，避免 Reviewer 只能看到 Producer 的摘要。遵守当前 manifest 的 allowed_steps。

## Judge

宿主明确接管复核时，Producer 在阶段 03 发布后结束本轮等待；不自行完成阶段 04/05 或填写独立 PASS。Reviewer 根据宿主给定的当前 run_id 和 review_request_id 写入已有独立审查状态文件：review_action 为 revise（交回原 Producer）、accept（本轮复核结束）或 wait（受阻）。这些字段只用于宿主精确续接，semantic_verdict 仍由 Reviewer 按证据决定。Producer 不改写该决定；收到修订要求后修原文件并结束本轮，由同一 Reviewer 复查。正式交付后仍由原 Reviewer 检查正式文件与已审内容一致。

- 深度型由宿主创建与 Producer 分离的真实 Judge 会话/子任务；记录实际 producer_session_id、reviewer_session_id 和宿主调用记录位置，禁止自编身份；无法获得独立执行能力时如实记录未完成独立审查；
- 独立读取完整设计契约、源码和工件；
- 不信任 Producer 的完成声明；
- 对计划逐项核对；
- 覆盖率分析发现缺口，在复核阶段内交回 Producer 定向修订原文件并复查，不重启已完成阶段。

逐项尝试推翻 Producer 候选：重新构造最小反例或反事实修正，检查同一修正是否消除多个所谓根因；核对参数声明，不能给整数入参套用指针 NULL 约束；检查覆盖缺口和范围外假设是否被误列成实现缺陷。

在 `活文档/复核记录.md`记录候选 ID、完整契约依据、反证尝试、保留/驳回/合并/待确认及原因。将审查发现写入已有 `review_issues`，指向受影响 ID/原文件与最小修订，Producer 修改同一正文和投影，Reviewer 复查，争议未解决保留 UNRESOLVED。

在现有 `内部索引/独立审查状态.json` 中如实记录 `independent`、`checked_artifacts`、上述会话证据，以及 Reviewer 自己给出的 `semantic_verdict`（`PASS` 或 `UNRESOLVED`）和 `summary`。这些是审查者声明；Python 不根据正文、字段数量或 READY 生成语义 PASS。速度型允许自审，但 `independent=false`，不能冒称独立审查。

## 缺口台账

只维护 `活文档/缺口台账.md` 的定位、分析、补测处置及未决项，不生成逐阶段 Coverage Gate 副本。

## 截断

达到执行预算时：

- 保存确认结果；
- 未搜索项标 truncated；
- 不得输出 READY。
