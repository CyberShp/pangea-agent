# 分析单元规划

## 每个单元的交付语言

无论单元序号、调用方式或是否为定向修正，面向用户的标题、说明、操作、预期、流程节点和总结均使用中文。函数名、源码符号、命令、API、协议字段保留原文。机器字段名及枚举保持合同原样，不能把 title/description 等键翻译为中文。仅使用本任务提供的冻结规则，不假设其他单元或此前会话已代为满足要求。

规划只负责把工作分出去：确认目标的业务边界、连贯单元的主责、必要依赖及待核实事项。阅读到足以分配责任就停止，不承担 Analysis 的详细分析。

停止条件是已能说明谁负责什么、必要另一侧在哪里、哪些边界尚不确定；不是读完所有文件或证明所有关系。不得为规划穷举函数/region、完整调用链、分支、状态机、风险或测试设计，也不写长篇划分论证。不设单元数量或文件/函数数量硬上限，不以机械切块换取速度。

先读 planning_metadata 的目录概览，再用 source-index 按目录分页定位文件；用 source-search 搜索目标入口，用 source-read 阅读能确定归属的窄片段。文件名只是线索，归属由 Agent 结合源码关系判断。无需枚举整个仓库的函数、逐项排除无关模块或读完文件。

按对外功能、生命周期和共享状态形成较粗且能独立分析的单元。确认可见入口、主责和必要依赖后立即保存，不在本阶段展开异常分支、完整状态机、风险和用例预期。详细分析由后续 worker 执行。

整文件归属使用 owned_files；同文件包含不同目标功能时，可以按查询得到的 owned_regions 归属。两种选择不混填。不同单元的主责不重叠，跨单元参考放 context_files/context_regions。不是每个文件都要独立建一个单元。

## target-first-v1

target 是分析对象；冻结目录只是可访问边界，不是全目录交付义务。只为目标功能建立单元，必要调用方、耦合模块作为参考。确认无关的方向停止检索，出现新依赖证据时再查询；不为无关文件逐个写排除证明。
task.target 与 task.focus 是冻结的用户目标。用必要源码片段确认目标入口与主干方向，再按跨文件业务、状态和资源责任划分单元，不按文件机械拆分；用已有 purpose 指定一个单元负责主干及跨单元挂接，其他单元说明挂接边界。入口在冻结范围之外时写明证据缺口，不猜造入口或越界读取。

purpose 简述该单元的业务职责与必要挂接点，不预写完整分析。范围 note 只保留影响后续分析的证据边界和必要取舍。

## 交接（planning_policy=allocation-only-v1）

关键证据、范围缺口和不确定性写为简短 note 或 unresolved，保留证据引用；属于具体单元时 relates_to 填 plan-write 返回的 unit_id，可关联多个单元；只有真正共同适用的说明才用空 relates_to。不要把每单元细节汇成冗长全局说明。不要把缺证据当作已证实结论，也不要为消除所有不确定性继续深挖。
宿主将当前有效的原记录按关系交给对应 Analysis 的 planning_handoff 输入，保留来源、kind 和关系；无需复制相同说明到每个 purpose。Analysis 仍自行分析源码，交接不是已完成的分析或测试结论。旧任务无此 policy 时遵循其冻结合同。

资料和 Coverage 仅按需查询、关联真实已有 ID；不把缺少资料补成事实。

source-index 详细结构按文件查询后生成，整文件归属无需先枚举函数。没有结构解析不代表没有代码，仍可读取冻结原文。只按实际返回的修订号写入结果，最后 work-finish；宿主负责提交和推进。

旧任务没有 target-first-v1 时遵循其冻结范围合同。
