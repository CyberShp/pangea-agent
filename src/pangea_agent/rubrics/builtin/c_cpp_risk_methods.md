# C/C++ 风险检查方法（risk-method-v1）

本文件给出 C/C++ 各镜头的检查程序。交付、账本、判据和记录格式以冻结的 scene_risk.md 为准。

## C/C++ 语义纪律

- 按真实求值规则推导：`a || b` 在 a 为真时不求值 b，`a && b` 在 a 为假时不求值 b；负数是非零真值。
- 先做整数提升和 usual arithmetic conversions，再判断溢出与比较结果。无符号运算回绕有定义，有时是有意的写法（例如用 `(unsigned)(c - '0') < 10` 一次判断字符是否为数字），要先读懂意图；有符号溢出是未定义行为。
- 宏按展开后的结果理解：实参可能被重复求值，被赋值的实参必须是左值。
- 区分数组与指针的 sizeof；区分条件编译的实际分支。

## 镜头一：异常路径（error_path）

枚举：每个函数中，已经产生副作用（申请资源、写调用方可见的输出或状态、修改全局或静态变量、加锁、改计数、关闭取消）之后的每个退出点——return、goto、跳出循环的 break、longjmp、abort/assert、回调返回的错误。

逐个退出点回答：
1. 此刻已完成的副作用，按执行顺序列出。
2. 哪些在退出前被撤销；没撤销的由谁负责（调用方、下一次调用还是进程退出）。
3. 返回给调用方的值：调用方是否检查；错误码会不会被后续成功覆盖、被吞掉，或被映射成"无结果"。
4. 失败时输出参数和调用方缓冲区处于什么状态；调用方会不会继续使用半成品。
5. 把这次失败接回下一次调用：static 变量、缓存、标志和计数是否复位。
6. 多后端回退（先 A 后 B）：A 失败留下的部分写入，B 是否会读到或覆盖不全。

常见形态：错误路径漏释放、漏解锁、漏恢复取消状态或信号掩码；错误码被覆盖；失败后输出半填充；正常路径和错误路径各释放一次；清理顺序错误导致使用已释放的对象。

## 镜头二：资源生命周期（resource_lifecycle）

资源包括堆内存、fd/socket/FILE、锁、取消状态与信号掩码、引用计数、定时器和注册项、线程、临时文件、内存映射。

1. 建账本：每种资源的获取点（含间接获取：返回新对象、通过输出参数交出所有权）、所有者、释放点、所有权转移点（返回给调用方、挂到全局表或链表）。
2. 从每个获取点沿全部路径（正常、每个错误退出、取消、循环提前退出）走到释放或转移。存在既不释放也不转移的路径，就是泄漏候选。
3. 对每个释放点：同一对象会不会被释放两次；释放后是否仍被使用（缓存的指针、未摘除的链表节点、仍登记的回调）。
4. 跨文件配对：申请和释放不在同一文件时，读取另一侧，核对双方对内存布局、计数初值、递减单位和所有权的约定是否一致。
5. 引用计数按对象逐次记账：初值、每次增减的位置和条件、减到 0 时的释放、计数类型能否容纳最大值、并发增减是否原子或受锁保护。
6. 取消与信号：获取与释放之间如果有取消点（阻塞 I/O、connect、poll、条件变量等待等），并且没有关闭取消或登记清理函数，线程被取消时资源由谁回收。取消点由范围外的实现决定、无法从冻结证据确认时，结论为 unresolved。
7. 获取失败：返回 NULL 或 -1 是否被检查；批量获取第 k 个失败时，前 k-1 个是否回收。
8. 栈上或静态对象也可能持有资源（例如对象内部保存的句柄），同样需要配对释放。

## 镜头三：边界值（boundary）

枚举：定长数组（局部、静态、结构体成员）、计数上限（MAX 类宏）、长度和大小参数、较窄的计数或下标类型（short、char、uint8_t）、循环上界、格式化输出目标。

对每个写入点和下标：
1. 写入长度或下标从哪里来（调用方参数、配置、文件内容、网络报文），最大能取到多少；把所有上游 guard 代入，包括调用方中的检查。
2. 与容量比较，包括结尾的 '\0' 和多段拼接（前缀 + 分隔符 + 后缀）。
3. 逐个检查极值：0、1、容量-1、容量、容量+1；空输入和最大长度输入；`len-1` 在 len 为 0 时的回绕。
4. 截断语义：fgets、strncpy、snprintf 截断后程序怎样继续——超长行的剩余部分会不会被当作新的一行解析；snprintf 的返回值是否被当成实际写入长度使用。
5. 计数上限：达到上限后是停止、丢弃还是越界；上限检查在写入之前还是之后。
6. 类型宽度：最大值能否装进存储类型；nmemb*size 是否可能溢出后再分配。
7. 读越界：按外部长度读取源缓冲区时，源是否真有那么长。

excluded 的 reasoning 写出代入极值的算式，例如"guard 保证 count ≤ 15，写入下标最大为 15，数组长度 16"。

## 镜头四：并发与时序（concurrency）

业务流程图表达不了交错。本镜头用"共享对象 × 访问者 × 操作"来分析，不用流程图代替。

1. 列共享状态：全局和静态变量、函数内 static、交给调用方后可能被多线程使用的对象、引用计数、缓存、会被其他进程修改的文件、errno 的保存与恢复。
2. 列参与者：同一接口的多个并发调用线程、回调上下文、信号处理函数、线程取消、fork 后的子进程、其他进程。
3. 对每个共享对象列出全部读写点和保护方式（锁、原子操作、初始化后只读、线程局部、每次调用的私有拷贝）。没有保护的写，加上任意并发读写，就是竞态候选。
4. 写出具体交错：T1 执行到哪一行，T2 执行哪一行，T1 继续，最终状态是什么。写不出具体交错的不算假设。
5. 锁纪律：所有路径上加锁和解锁是否配对；多把锁的顺序是否一致；持锁期间是否调用可能阻塞或回调用户代码的函数；锁是否覆盖完整的"检查—使用"区间。
6. 取消和信号安全：取消点的位置（见镜头二第 6 条）；信号处理函数是否调用了非异步信号安全的函数。
7. 可重入：是否用静态缓冲区返回结果。

confirmed 需要具体交错序列和引文。并发模型或调用约定无法从冻结证据确定时，结论为 unresolved，写明需要哪项线程模型或调用约定。

## 镜头五：不可信输入（untrusted_input）

信任边界：网络报文、本地配置和数据文件、环境变量、调用方传入的字符串/长度/结构体、跨进程消息。优先级：网络 > 本地文件 > 调用方参数。

对每个解析器或消费点：
1. 每个长度、计数、偏移字段：使用前是否与剩余缓冲区长度比较；有符号与无符号转换前后比较是否一致。
2. 循环是否有界（指针跳转可能成环）；递归深度。
3. 字符串是否保证以 '\0' 结尾；最大长度；嵌入的 NUL 和非 ASCII 字符。
4. 构造反例输入：空和最短、超长、长度字段与实际长度不符、重复或嵌套、越界偏移、类型字段与长度不匹配。
5. 解析失败时的状态：部分写入的输出；失败是否被当作"无数据"继续处理。

## 镜头六：契约差异（contract）

1. 正确预期的来源：冻结的需求或设计、头文件注释、公开规范（POSIX、RFC、协议规范）。引用规范时写明规范名称和条款；记不清细节时结论为 unresolved，不得把记忆中的细节当作冻结证据。
2. 逐个公开入口核对：参数合法域、返回值和错误码集合、失败时输出参数的状态、线程安全约定、所有权约定（谁负责释放）。
3. 区分三种情况：实现违反契约（风险）；只有调用方违约才会触发（excluded，理由写 API 误用）；契约未规定（unresolved 或写入说明，不作为风险）。

## 已知陷阱

- `if (v < 0) return -1;` 本身不计算 `-v`，不会发生取负溢出；不要用相反的比较结论构造风险。
- `assert` 在 Release 构建中被移除；Debug 构建在 assert 处终止，不能用其后的清理代码证明 Debug 路径能恢复。
- 实现注释、assert 和"调用方保证"只说明实现依赖某个前提；只有公开契约明确规定，或入口代码实际检查并阻断，才算调用方保证。
- 共享代码不代表共享语义：多个 case 或多个实现共用一个 handler 时，按每个前驱状态分别追踪。
