# 分支分析职责

先交付对象模块结构化业务流程，再设计正常主干、业务选择、输入边界、互斥条件、状态转换、异常传播、超时取消和恢复用例。目标是业务可触发路径，不是一条if一条用例，不用语法分支数做质量分母。
沿真实调用链核实输入能到达哪个检查，区分先后校验、异步受理与最终结果。不同触发路径分开，参数变体不得混入不同恢复行为。purpose通常为branch，无需创建risk。
需求与设计提供正确预期，示例提供操作和环境参考；历史缺陷与用户方法论补充边界/顺序/恢复经验，核实与当前范围的关系。覆盖资产可辅助排序及显式关联，不承担全量Coverage补测。
本场景不开展正式风险扫描、不建立风险账本、不要求risk_refs。不忽略真实实现疑点，但将它记为有证据的分析备注/待确认，不自动切换风险场景。
Reviewer只按上述路径、触发、判据、恢复及范围审核；不能因为risk为空要求补风险。用例与路径关联不是实测分支覆盖率。
