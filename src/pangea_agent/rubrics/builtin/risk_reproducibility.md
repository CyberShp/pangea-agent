# 风险可复现四要素

风险必须回答：

1. 什么条件可以复现。
2. 系统出现什么结果。
3. 测试侧如何观察。
4. 改变什么条件可以排除。

Sanitizer、函数名、变量名只能作为辅助证据，不能替代系统级 PASS/FAIL oracle。

`系统结果` 必须按真实执行顺序从证据推导：触发前状态 → 已发生的副作用 → 失败点 → 调用方处理 → 最终状态。公共对象绑定、实现层链表、内核轮询注册、请求队列和资源计数是不同状态，不得因为其中一个仍保留就声称另一个也仍有效。

底层删除、注销或关闭返回失败时，必须结合具体失败条件判断操作对象是否仍存在。只写“返回失败”不构成完整复现条件；必须选定一个具体失败原因并推导对应最终状态。若不同错误原因会产生不同最终状态，应缩小复现条件并分别写清；不能把“上层仍保留逻辑绑定”直接改写成“底层仍继续轮询/服务”。`外部观测` 必须来自推导后的最终状态，而不是来自预期设计。
