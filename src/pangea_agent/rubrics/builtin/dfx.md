# DFX 六维风险分析

只在源码、当前实现规格或可信资料存在信号时形成风险；未发现信号时明确写“未发现”，不得为了填满六维而编造风险。一个风险可以命中多个维度，但必须分别说明依据。

## 1. 功能与状态

- 覆盖初始化、运行、停止、恢复和卸载的完整生命周期。
- 沿业务入口追踪正常、异常和分支流程，以及状态迁移、重复操作和恢复结果。
- 用测试人员可理解的黑盒业务语言描述流程，函数、变量和行号只作为证据。

## 2. 资源与规格

- 追踪申请、所有权、额度、耗尽、回收和重复释放。
- 覆盖队列及内部资源，例如 SQ、SRQ、CQ、TX、RX，以及连接、请求和缓冲区。
- 从源码提取配置默认值、范围、依赖和代表性组合，不展开无依据的全量笛卡尔积。

## 3. 性能与压力

- 关注并发规模、队列深度、长期运行、资源上限和恢复后的性能。
- 检查等待锁、持锁空耗、慢路径放大和异常重试是否造成吞吐下降或时延抖动。

## 4. 并发与异常

- 明确参与者、共享对象、锁、回调上下文和关键时序。
- 检查失败返回、超时、取消、竞态、重复回调和清理交错。
- 分支覆盖需要关注判断结果两侧；缺少覆盖率不能被测试用例语义代替。

## 5. 升级与兼容

- 仅在升级路径、固件交互、持久化格式、协议字段或结构体变化存在信号时分析。
- 说明新旧版本组合、升级/回退步骤、数据或连接存续，以及外部可观测结果。

## 6. 可靠性与一致性

- 主要关注协议数据保护与校验，例如 DIF/PI、digest、CRC 及校验失败后的处理。
- 没有对应实现信号时不生成此类用例；不能把一般文档差异当作数据一致性风险。

## 每个风险的最低证据要求

风险必须包含复现条件、系统结果、外部观测、排除条件、严重度、置信度和源码证据。风险是否真实存在与当前是否容易测试是两件事；需要开发协助打桩时保留风险并明确测试条件。
