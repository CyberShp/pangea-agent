# C/C++ 源码分析方法

关注入口、调用链、状态机、错误路径、异步回调、销毁/恢复路径。

重点抽取：

- 外部入口、协议事件、CLI/REST 和状态机迁移。
- 资源所有权、申请/释放、引用计数、队列额度、预留与动态内存。
- 错误处理、清理、重试、取消、超时、初始化、卸载和复位。
- 共享状态、锁、原子、回调上下文和 C/C++ 边界。

错误行为已写入接口约定，只能证明“可能返回错误”，不能证明错误后的状态安全。若回调或底层实现可能先修改资源、链表、引用计数或句柄状态，再返回失败，必须继续检查部分副作用、调用方补救以及后续重试、关闭和恢复是否仍然可执行。为确认直接回调的副作用，可以读取 task 已提供的直接实现文件，但不得递归扩大范围。

遇到 `assert(false)` 后仍有清理或返回语句时，分别判断 Debug 与 Release：Debug 可能在到达清理前终止，不能用后面的清理代码证明该路径能够恢复。

`assert(false)` 由受支持运行模式中的底层调用失败直接触发时，先检查公开契约或入口是否实际阻断该失败。若没有阻断，Debug 进程终止是该路径的真实最终状态，不能仅以“fail-fast”或 Release 构建会清理为由排除。

实现注释描述“无法处理”、assert 某状态或假设某队列为空，只能说明实现依赖该状态，不能单独证明公开调用方已经承担了前置条件。只有公开接口契约明确规定，或入口代码在进入实现前实际检查并阻断，才能作为调用方保证。若 Release 构建移除断言后继续解除对象与容器的关联，必须继续核对未归还资源是否仍有可达的所有者和释放路径。

共享 helper、引用计数或公共状态被多个直接实现调用时，按实现分别检查进入条件、失败处理和退出状态。一个实现返回错误阻断后续操作，不代表另一个忽略错误继续执行的实现也安全；不同实现的结论不能合并成一个“不可达”或“未确认”。

句柄、索引或计数参与数值边界判断时，先查创建函数的真实失败返回值和同文件的无效值约定。失败值为 -1 不代表 0 也无效；必须分别重放 `< 0`、`<= 0` 与 `== 0` 的边界，不能用“通常为正”或“退化环境”代替契约。

引用计数或资源配对风险必须由一条真实调用序列证明：哪次操作成功增加，哪次增加失败或被跳过，错误返回如何传到上层，上层是否仍完成绑定，最后哪次减少因此失配。错误日志后的注释不能代替函数返回值；lookup 不增加引用或局部代码看似不对称，本身也不能证明后续减少失配。

先证明操作真的被调用，再讨论它成功或失败。分支 guard 跳过 insert/acquire 与调用后返回错误是两条不同路径；后续状态可能相似，也不能把二者写成同一个失败机制。

状态断言与资源存在性相关时，检查完整时间顺序：状态可能在资源存在时置位，随后公开重配置、禁用或销毁资源却漏清状态，最后才在资源为空的分支触发断言。只证明当前分支不会新写入该状态，不能证明此前状态不会残留。

断言可达性与资源重配置后果要分别形成 failure path。断言本身可被入口条件或紧邻清理保证，并不代表状态置位后销毁资源也安全；后者仍要独立检查数据是否丢失、通知是否残留以及状态是否同步清除。

关闭、销毁、注销或释放不只是项目内字段变化。继续检查被操作对象的契约，以及操作系统、运行库或框架会自动移除的注册、事件和引用。只有残留状态在这些清理之后仍能被证明存在，才能形成风险；若需要重复句柄、并发中已经返回的事件批次或延迟回调，必须把它们写入真实调用序列。当前冻结输入无法确认外部语义时保留 unresolved，不用未经核对的常识补成确定结论。

风险集合冻结前，反查每条 `excluded` 的公开契约或入口阻断位置。只有实现注释、assert、`fail-fast` 或“调用方误用”而没有实际阻断代码时，不足以证明不可达。

高影响路径若因冻结范围不足只能判为 unresolved，仍要进入风险账本：使用低置信度、`upstream_semantics.conclusion=unresolved` 和 `translation_status=Developer-confirm` 说明缺口。它不生成伪可执行用例，但不能从交付报告消失。

同一个检查若同时得到一个已确认后果和另一个独立的高影响 unresolved 后果，分别记录 failure path 和 RiskCard。未确认后果不能作为“子项”并入已确认风险，否则 `risk_remains` 会掩盖它仍需确认、不可直接生成用例的事实。

正常调用链梳理后，在源码范围和任务已提供的 C/C++ 直接实现、内联头文件中，单独从显式终止点、状态修改后的失败返回、被忽略或改写的关闭错误反向追触发条件。这个步骤用于发现高影响候选，不递归扩大文件范围，也不要求把每个普通错误返回都登记成风险。

输出必须先转成测试人员可制造的外部条件、可观测行为和恢复标准，再在证据中引用函数、变量和行号。
