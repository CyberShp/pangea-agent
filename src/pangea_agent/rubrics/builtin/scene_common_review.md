# 场景共同复核

仅用于behavior-test-v2。必须读取analysis_scene、scene_flow、当前场景规则及已选方法论，以同一冻结职责评审。
标准型 independent_review 只读冻结源码、输入和中性单元计划，不读取首轮结果；独立识别主干、必要路径和当前场景核查项，保存简洁依据。Comparison续接同一Reviewer，读取锁定首轮版本逐项对照，不重新生成整套用例。速度型直接comparison。

检查：范围是否为target及必要依赖；模块结构化业务流程是否说明入口、主要步骤、关键判断、状态、异常恢复；与源码和用例是否一致；用户操作、可制造条件、外部判据、清理及再次操作是否有依据。
按 scene_flow 核对结构化业务流程的节点、连线和路径；只有 text 不能替代流程交付。缺失时由 Reviewer 向原 worker 提出具体补齐要求，保留已核实内容；不要求尚未生成的用例编号，不由 Python 猜造流程或增加硬门禁。不同触发路径不能混为一条用例，连续校验中先退出的输入不能声称覆盖后面的检查。
黑盒与可实施灰盒保持既有70%目标，由Reviewer结合正文判断；needs_instrumentation不冒充可执行，白盒内部函数调用不冒充产品操作。零新增用例的真实结论按其依据审核，不以数量补造用例。
branch/coverage不检查正式风险完整性，不要求补存risk或risk_refs；产品疑点可以记录待确认。review finding是交付质量问题，不等于产品风险。
Coverage仅按真实引用及实际业务触发核实，行号重叠不证明能补测；无数据/无分母不宣称100%，生成用例不代表实测覆盖提高。示例用例不是执行记录。
同一unit的具体差异集中为finding，带原文/反证及真实目标记录；资料不足记UNRESOLVED。定向修正续接原worker，只修受影响内容，不增加完整复核轮次，不改写原首轮结果。
