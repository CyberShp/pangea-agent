# 场景共同复核

仅用于behavior-test-v2。必须读取analysis_scene、scene_flow、当前场景规则及已选方法论，以同一冻结职责评审。
标准型 independent_review 只读冻结源码、输入和中性单元计划，不读取首轮结果；独立识别主干、必要路径和当前场景核查项，保存简洁依据。Comparison续接同一Reviewer，读取锁定首轮版本逐项对照，不重新生成整套用例。速度型直接comparison。

检查：范围是否为target及必要依赖；模块结构化业务流程是否说明入口、主要步骤、关键判断、状态、异常恢复；与源码和用例是否一致；用户操作、可制造条件、外部判据、清理及再次操作是否有依据。
按 scene_flow 核对结构化业务流程的节点、连线和路径；只有 text 不能替代流程交付。缺失时由 Reviewer 向原 worker 提出具体补齐要求，保留已核实内容；不要求尚未生成的用例编号，不由 Python 猜造流程或增加硬门禁。不同触发路径不能混为一条用例，连续校验中先退出的输入不能声称覆盖后面的检查。
黑盒与可实施灰盒保持既有70%目标，由Reviewer结合正文判断；needs_instrumentation不冒充可执行，白盒内部函数调用不冒充产品操作。零新增用例的真实结论按其依据审核，不以数量补造用例。
branch/coverage不检查正式风险完整性，不要求补存risk或risk_refs；产品疑点可以记录待确认。review finding是交付质量问题，不等于产品风险。
Coverage仅按真实引用及实际业务触发核实，行号重叠不证明能补测；无数据/无分母不宣称100%，生成用例不代表实测覆盖提高。示例用例不是执行记录。
对涉及算术的路径核对类型、整数截断、缩放及回绕后的关键中间值，使用具体输入验证分支和预期；原始分母非零不能替代最终除数检查。来源限制被正文越过、关键分支结果或中间值边界遗漏属于具体内容问题，交回原worker修正，不以渲染成功或格式完整代替语义复核。
Comparison 先在现有 note 中按 unit_id、record_id 和变体标识保存逐项核对依据，再作裁决。覆盖所有正式及辅助用例，不能找到一个错误就概括其余用例正确；这是当前对照复核的工作，不新增复核轮次或数据格式。
- 数值预期：列出输入、关键转换/赋值后的中间值、实际结果与原 expected 的对照。每个 variants 也核对；“总是小于/等于”等范围断言须检查截断区间两端及反例，单个成功算例不证明范围结论。
- 宏调用：按展开后的读写核对实参，凡参数被赋值，确认步骤使用可修改变量并说明初值和调用后值；常量或临时结果作为被写实参是用例错误。重复求值与副作用按源码检查。
- 执行准备度：逐条核对 execution_readiness 和 readiness_reason，包括辅助用例。ready 须有入口、现有触发设施和观测的来源依据；尚需编写驱动/桩时是 needs_instrumentation，入口尚未核实时是 unknown。漏填或无依据标 ready，交原 worker 按实际证据补正；合成 Coverage 不决定此状态。
流程逐边查证调用点或函数内顺序，逐条检查 paths 的相邻节点是否有对应边、真假分支是否有不同处理节点、清理/重置是否在返回之前。只写“公式正确”“流程正确”不能代替这些依据。
有明确源码反证且原 worker 能修改的记录，使用 comparison-finding-write 保存具体 finding，并将返回的 record_id 放入 review-decide 的 correction_record_ids，disposition=finding；这会触发现有定向修正。仅无法确定的事实使用 unresolved。不要因缺少执行设施而放过已确定的预期错误，也不要把合成 Coverage 本身当成用例不可执行的理由。
同一unit的具体差异集中为finding，带原文/反证及真实目标记录；资料不足记UNRESOLVED。定向修正续接原worker，只修受影响内容，不增加完整复核轮次，不改写原首轮结果。

已确认某个 expected、步骤或变体与源码/执行反证矛盾，即使核心覆盖目标仍成立，也必须通过 comparison-finding-write 指向该原记录，再由原 Worker 定向修正；不能仅保留备注或以 unresolved 代替已确定的修正。当前任务有小型执行证据时核对实际输入、输出、退出码及桩限制；若执行与静态推导不同，先核对类型和编译条件，不静默采用理想公式。
