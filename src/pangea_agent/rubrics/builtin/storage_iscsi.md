# iSCSI 专项分析方法

## 适用条件

只在冻结源码或当前资料中出现 iSCSI target/initiator、Login/Text/Logout PDU、CHAP、
session/connection、CmdSN/StatSN、SCSI task 或明确的 iSCSI 恢复状态时采用本方法。
仅有 TCP socket、SCSI 命令或通用认证代码不足以套用 iSCSI 结论。

先确认当前实现角色、支持的协议阶段、错误恢复级别、连接数和认证方式。规范、Linux
open-iscsi、LIO 或 SPDK 的行为只能提供核对方向；目标源码没有实现或声明的能力不能写成当前事实。

## 分析步骤

1. 从产品入口建立 `portal/target -> session -> connection -> task` 层级，标出 discovery、
   login、正常 IO、logout、连接恢复和 session 终止的外部入口与状态。
2. 重放 Login 的安全协商、参数协商和进入 Full Feature Phase 的顺序。逐项记录每个阶段成功前
   已创建的 socket、connection、session、认证上下文、定时器和 SCSI 资源，以及失败时由谁撤销。
3. 对 CHAP 分开检查 discovery 与普通 session、单向与双向认证、缺失/错误凭据、算法无交集、
   重试和凭据变更。只有源码明确支持热更新或重新认证时，才分析既有连接是否保留或断开。
4. 沿真实读写路径追踪 command、data、response/status 的发送、确认、超时和完成。确认一个请求
   在失败前是否已经入队、下发、部分传输、上报完成或释放；不能用最终错误码代替中间副作用。
5. 若实现处理 CmdSN/ExpCmdSN、StatSN/ExpStatSN、DataSN 或 R2TSN，分别确认其作用域、递增点、
   确认点、重传规则和回绕比较。CmdSN 的 session 作用域与 StatSN 的 connection 作用域不得混写；
   immediate、重发或新连接是否推进序号必须由当前分支证明。
6. 对多 connection session，逐连接记录 CID、连接归属、任务归属和响应路径。一个 connection
   失败不能自动推导为整个 session 终止，也不能用其他连接仍在线证明失败连接上的任务已恢复。
7. 从 TCP 断开、digest/序号错误、登录超时、认证失败、target 重启和主动 logout 分别进入恢复路径，
   追踪是重试 command、重建 connection、重建 session，还是向上层失败。不同恢复层级不得合并。
8. 恢复结束后继续验证旧任务的唯一终态、新 IO 能否进入、LUN/设备是否仍可见，以及定时器、队列、
   session/connection 记录和认证材料是否回到可再次登录的状态。

## 证据与风险判定

- 每条结论必须绑定一条完整时序：业务入口、协议阶段、失败点、已发生副作用、调用方处理、最终状态。
- 参数默认值、超时、重试次数、恢复层级和允许的连接数只从当前源码、配置 schema 或现行资料提取。
- 只看到序号不连续、重试分支或清理函数不足以形成风险；必须证明受支持输入可达，并落到 IO、连接、
  设备、进程或恢复能力的外部结果。
- 登录失败后资源被完整撤销且下一次可正常登录时，这是已处理错误，不保留 RiskCard。
- 若无法确认 peer、内核 SCSI 层或 TCP 关闭对任务和注册状态的处理，保留 `UNRESOLVED`，明确缺少的
  外部语义；不得用某个参考实现补成目标行为。
- 认证错误属于预期拒绝时，风险检查重点是未授权连接是否建立、失败是否泄露既有 session、以及正确
  凭据恢复后能否重新登录，而不是把“拒绝登录”本身写成风险。

## 转换为测试

- 正常基线从 discovery、login、LUN 可见和读写成功建立；异常用例只改变一个认证、连接、序号、
  超时或 target 状态条件。
- 协议字段、乱序、digest 或重传条件需要内部工具制造时写成灰盒前置条件；测试步骤仍使用产品正常的
  登录、断链、重连和 IO 入口，主要判据是连接、设备、IO、服务、日志或指标。
- 断链恢复用例必须写清断开前的在途 IO、断开动作、恢复等待条件、在途 IO 终态、新 IO 结果和清理。
- 认证用例分别覆盖正确、错误、缺失及双方能力不匹配；只有当前实现支持时才增加凭据轮换和重新认证。
- 重复登录/退出或连接恢复测试要在每轮后观察资源回到基线，并在最后一次恢复后执行真实 IO；循环次数
  来自现行规格或源码边界，不用任意大数代替可复现条件。
- 每个 TestCase 使用一个恢复层级和一个唯一终态。需要重启服务后验证恢复时，重启并等待就绪必须是
  独立步骤，不能继续使用已经失效的旧 connection 或旧设备句柄。
