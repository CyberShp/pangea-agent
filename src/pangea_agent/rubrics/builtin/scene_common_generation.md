# 场景分析共同规则
当前场景规则与本文件对同一事项规定不同时，以场景规则为准。

仅用于 behavior-test-v2。先读 analysis_scene；按 scene_flow 先保存模块结构化业务流程，再开展当前场景工作。

## 按需使用已选测试工具参考

当前 task 的 test_tool_reference_paths 是用户为本 Run 冻结的测试能力参考，不是被测对象；只用现有 source-search/source-read 按需核实，不对工具做分支、风险或覆盖分析，不全量阅读工具仓库，不执行工具，也不要求用户先写完整操作说明。
当候选用例缺少操作入口、参数、外部观测或清理/恢复方法时，先在这些已选路径中检索入口脚本、参数定义、示例及必要实现；确认真实能力及适用前提后再写操作。没有选择参考或冻结材料仍不足时，保留测试目标和具体缺口，不猜子命令、参数、时限、注入开关或越界找新版本。

复用现有 kind=note 保存共用操作说明：body 使用已有 title、note_id、content、source_evidence 等字段。content 面向执行人员写清执行主机与目录、工具/产品版本及环境前提、带占位符的真实命令模板、参数单位/取值和填法、工具自动完成的行为、外部观测入口、清理/恢复及其依据。未知项明确写未知；命令模板的注释只解释操作，不把内部推演或每例的产品预期塞进共用说明。源码位置使用 repo_id:path:line，记录“已核对冻结资料，未实际执行”。不要求每条用例复制整份共用说明。

用例通过现有记录顶层 relates_to 关联操作 note，例如 [{"unit_id":"U1","record_id":"实际保存的note记录ID"}]；同单元也可用已保存 record_id 字符串。必须使用保存后返回的真实 ID，不把 note_id 当 record_id，不发明 body.note_refs。每条用例仍在 preconditions、steps[*].action/expected、variants 和 cleanup 写明本例具体对象、实际参数值、顺序、外部预期与恢复要求，不能只有“参见工具”。共享模板不能代替具体步骤或预期。

工具若只支持 connect/query，不得为暂停、篡改报文或精确命中认证窗口发明 pause/reset/send-message 能力。主机自动认证写为 connect 后的自动行为及外部观察，不能逐消息伪写成人工操作；内部状态/函数仅作依据，不作为主要判据。缺少控制或观测设施时保留目标，使用 needs_instrumentation；入口或结果依据尚未核实用 unknown，并在 readiness_reason 列明缺口。ready 仅表示设计已有依据，execution_status 仍为 not_run，未接设备不等于缺设施。

## 核实一次操作的实际结果

- **看用户最终收到什么。** 从最外层产品入口追到响应写入或完成回调。异步内部函数返回 0
  可能只表示受理成功；若 RPC 等待完成回调，测试预期采用该回调最终返回给用户的结果。
  日志、返回数组、布尔值和设备名使用实际输出，不由函数名或内部返回值推测。
- **写明配置何时改变。** 操作前使用旧值 A，修改时使用不同的新值 B；逐步核对每一侧的
  当前值。preconditions 是第一步执行前同时成立的状态快照；本次要做的配置改变只写在
  steps.action。前置已完成的连接不再重复创建，清理恢复所有本次改变的配置及创建的对象。
  若先用正常输入验证环境，验证结束后应清理该连接，再开始使用同一名称的异常测试。
- **沿真实终态继续。** 失败后的重试继承实际连接、资源和配置状态。只有真实恢复、重建
  或自动转换才能改变它们；先核对底层守卫、异步资源及回调，再确定第二次操作结果。
  不能把启动前被拒绝等同于事务已启动后失败。
- **让故障可制造。** 核实故障设施、触发条件和恢复方式。没有交付的报文篡改器、内部同步
  开关、内存故障桩等不能假定存在；保存具体触发缺口及源码处理依据。辅助接口用例同样
  需要实际的触发方法、可观察的执行时机和清理方法；“认证正在进行中”等内部状态本身
  只是待制造的条件。方法未确定时，在 summary 保留该分支依据及缺少的执行条件。
- **按路径核实边界。** 使用真实比较式、调用方向和条件编译替代实现；正常完成、超时、
  取消分别核对状态与资源归属。C/C++ 按求值、类型和宏理解，Lua 按返回值、异常和清理理解。
  引用 callee 的实际终态，资源次数按该路径的调用点核实；相似状态分别确认错误分支。
  连续校验按执行顺序逐项追踪：在格式检查处退出的输入不能覆盖后面的长度或校验和错误。
  后续检查需要能通过前面检查的独立输入；尚未准备该输入时，说明具体缺口。
- **沿中间值检查算术边界。** 按实际类型、求值顺序跟踪整数截断、缩放、转换和回绕后的值，
  再检查除数、索引及比较条件。初始值非零不保证运算后非零；用具体输入核对预期，保留
  触发路径的前置条件。静态可构造的局部边界不等于已证明从产品入口可达或已执行。
  每个数值 expected 和 variants 在保存前逐句代入源码验算，在独立 note 按用例及变体标识保存“输入 → 中间值 → 返回值/异常”的短算例。声称“总是小于/等于”时还须检查截断区间的两端，不能用一个例子证明整个范围，也不能用理想数学公式替换实际整数求值。分母、索引等敏感中间值还要检查经过截断后变成零或越界的边界。
- **按展开结果检查宏调用。** 对测试步骤中的宏实参逐项核对读、写和重复求值；被赋值的参数须传可修改左值，写明变量声明、初值及调用后的值。常量、临时结果不能代替被写入的变量；有副作用的实参还须核对求值次数。区分“将变量置为 0 后调用”和“传入常量 0”。
- **区分计时范围。** 产品超时、重连间隔和实验观察窗口各自有起点和结束条件；采用真实
  完成条件，不按参数名称相加推断响应时限。源码已能回答的结果继续读完依据再下结论。

以上核实用于 Analysis 理解和源码依据。共用操作 note 面向执行人员，只保存准备环境、
命令和参数填写方式。产品响应写在对应用例的 expected 中，流程沿用该结果；共用命令的
注释只解释参数用途。内部实现推演仅在结论确实需要时单列证据。

## 从关联逻辑提炼场景，再确定用例粒度

在本轮源码阅读中先说明：谁，在什么业务阶段，执行什么操作或遇到什么事件，需要验证什么行为。
product-behavior 以产品行为为目标；interface-contract 可以公开接口的输入、调用顺序、返回和资源契约为目标。
上下关联的判断、helper 调用与清理步骤是理解场景的依据，不能直接按代码路径拼成一条用例，
也不能按 if/else、函数、流程节点或内部变量的数量决定用例数量。只把内部符号翻成中文仍不是场景提炼。

- **结合注释核实业务含义。** 阅读关键判断附近的注释、函数职责、调用上下文，以及相关状态的设置和清除位置。
  注释解释意图，实现说明成立条件和当前行为，需求/设计/协议或接口契约提供正确预期；相互冲突时分别保留依据和待确认事项。
  没有独立预期依据时标明当前结论仅为源码推导，不能把代码当前行为自动当成正确答案，也不扩大冻结范围。
- **区分条件的作用。** 定义业务情形的条件保留在场景中；操作后自然形成的内部状态用于证明触发关系，
  不写成人工置位步骤；到达目标处理所必需的条件，追查并转为实际准备或触发要求。
  内部保护、辅助分流和清理细节先判断是否揭示独立验证目标；没有则留在依据中。
  含义或必要性未知时保留具体缺口，不能因为它出现在路径上就加入前置，也不能随意删去。
  资源申请失败等内部条件若对应真实故障情形，继续核实外部触发或已有灰盒设施，不因去白盒而丢掉场景。
- **按验证目标拆合。** 一次业务情形自然经过多个关联判断，或跨多个函数/文件，不据此拆例。
  独立故障条件、关键事件交错、业务/接口契约或恢复要求需要分别验证时，保留独立目标并说明拆分理由。
  相同外部结果、错误码或共享 handler 不证明业务等价；不同内部代码路径也不证明业务不等价。
  不因都断链成功而合并普通关闭与关闭交错，也不因 FIN/RST 与标记取值就自动生成全组合。
  同一场景的操作、主要判据和恢复一致的数据变化可放 variants，每个变体保留实际输入与预期。
  这里的顺序指测试人员的实际操作或有业务意义的事件时序，不是内部求值和调用顺序。
- **保留简短推导。** 在已有 note 中关联业务情形、验证目标、必要条件、触发手段、主要判据、源码依据与拆合理由。
  分支场景复用 behavior-coverage-v1 的 items/reason、其他场景复用现有分析 note；不逐个 if 建账，
  不新增记录合同、转换 Agent、全局阶段或 Python 语义门禁。比例和数量不能代替上述判断。

## 短用例示例

示例用于学习写法，实际功能与预期需要当前任务的证据支持。

**正确密钥连接成功**

- 前置：目标要求认证，主机配置匹配密钥，本次连接和设备不存在。
- 操作：主机连接目标，查询连接和设备。
- 预期：连接成功，出现本次连接及连接命令返回的设备。
- 清理：断开本次连接，查询确认连接和设备移除。

**错误密钥被拒绝，修正后恢复**

- 前置：正确密钥已验证能连接并已断开，目标配置保持不变。
- 操作：使用格式合法但不匹配的密钥连接；确认失败后改回正确密钥重新连接。
- 预期：首次被拒绝且没有本次连接和设备；修正后连接和设备出现。
- 清理：断开本次连接，查询确认连接和设备移除。

**在线更新密钥**

- 前置：主机与目标均使用密钥 A，现有连接和设备可用；主机已注册不同的新密钥 B。
- 操作：目标改为 B；主机对现有连接提交 B；查询连接和设备。
- 预期：更新成功，原连接及对应设备仍可查询到。
- 清理：断开本次连接并确认移除，将目标密钥恢复为 A。

**主动关闭过程中收到对端 FIN：场景骨架**

- 目标：验证主动关闭与对端关闭交错时，目标连接按约定结束。
- 必要条件：核实主动关闭标记的来源、有效窗口及前序约束；“在途数据”等只有确为必要时才保留。
- 操作与判据：通过已提供的真实关闭入口及已核实的时序控制/确认手段触发，使用连接查询、协议记录等确认约定的结果；撤销控制措施并恢复环境。
- 依据：内部标记、状态机、函数调用和清理动作单列证据，不逐项改写成操作及主要预期。

本例不提供具体产品命令或注入设施，不能直接标 ready。“同时关闭”或“制造交错”只是条件描述，
不能证明命中目标窗口；尚未实测与根本缺少控制/观测设施分别记录。无崩溃也不证明无内存破坏，
内存安全观察点须有相应依据与真实诊断设施。

## 在本轮把内部路径转为可执行场景

对每个候选按以下四步完成分析与写作，不另开转换回合；已有场景 note/items/reason 复用即可，不新增合同。

1. **映射条件。** 从目标入口追查内部条件的设置、清除和使用，把必要条件对应到执行人员能建立的
   外部准备、输入或事件；操作自然产生的状态只作为触发依据。写清谁、业务阶段、验证目标与恢复要求，
   不按内部判断/回调/清理调用逐项生成步骤。尚不能映射的条件保留具体缺口，不删除真实故障场景。
2. **确定刺激和观测。** steps.action 写实际入口/工具及操作（或引用已核实的共用操作 note）；
   steps.expected 写通过该入口的响应、连接/设备查询、I/O、协议记录或有依据的指标能判定的结果。
   每个expected中的每个断言（包括并列、附加及variants预期）均明确观察对象、方法与成功/失败区别；“正常处理”“正确关闭”“无泄漏”不能替代判据。
   内部回调发生、变量置位、helper 被调用或内部队列状态不作产品黑盒判据，即使中文化也不行；不能用一句外部成功夹带未证实可观察的内部终态或资源释放。
   自动完成的协议交互写为观测，不伪写成人工逐条发送；只有已核实工具提供相应控制时才列为操作。
   协议报文、公开状态字段和同名私有枚举分别核实来源与观测边界，不按词名删除合法消息或公开接口判据。
   连接成功、后续可用或再次连接成功不证明本次认证资源已释放；资源断言须有真实观测设施、对象归属、基线及完成条件，否则保留验证缺口，内部清理推演仅作证据。
   对每步反问：不查看私有函数/变量，执行人员能否判定？不能则继续寻找观测或保留未知，不能只删符号。
3. **单列依据，保留真实层级。** source_evidence 和关联 note 保存内部因果与已读源码位置，正文保留
   实际必要的协议字段、报文、抓包和技术参数。product-behavior 优先外部行为；interface-contract
   可直接验证有证据的公开 API 输入、调用顺序、返回、公开状态及资源契约，不将公开函数误删为白盒。
   灰盒允许精确写出内部注入点，但须有现存工具/桩、目标请求、阶段、值/延迟、次数/时间窗和撤销方式，
   由外部业务触发并以外部结果作主要判据；延迟对照真实计时区间及阈值，撤桩后验证恢复。
   私有函数直接调用仅在任务需要且可运行测试桩有证据时保留为开发辅助，不冒充公开 API 或产品入口。
4. **核实准备度后保存。** 每条正式及辅助用例均填 execution_readiness 和 readiness_reason，引用入口、
   触发设施、观测来源或明确缺口。ready 仅表示设计可执行，不代表实测，execution_status 仍为 not_run；
   已有设施但设备未连接不必降级。需新增注入/观测设施为 needs_instrumentation，入口或结果依据尚未核实为
   unknown，不计入可实施用例；“可编写测试桩”不是现有设施。只有内部推演而无场景时保存 note/evidence。
   保存后发现问题仅定向替换受影响记录，保留有效内容与源码依据。正常业务拒绝不自动成为风险。

### 成对示例：握手未继续，不能以回调代替判据

以下 symbol_* 都是占位符，不指向具体产品。未提供的阈值、命令、报文和关闭方式不得据此补造。

- **反例（内部判据）**：发送合法 symbol_init_request 后保持连接但不发送 symbol_connect_request；
  预期“symbol_timeout_callback 回调，symbol_connected 未置位，调用 symbol_close，symbol_queue 消失或关闭”。
  操作可能是外部刺激，预期却只能靠实现细节判断；把 symbol_* 换成中文仍不解决问题。
- **反例（只去符号）**：同一操作，预期“超时后正常处理、连接正确关闭”。未说明何时、从哪里、对哪个连接
  观察到什么，不能验收；不能凭示例把某个等待秒数或 FIN/RST 当成产品契约。
- **正例（有证据才可 ready）**：已核实协议工具支持发送 symbol_init_request、抑制 symbol_connect_request，
  并观察该会话连接；以已核实的计时起点和配置 symbol_timeout 为准，执行该操作，在证据规定的观察窗口内
  通过该工具确认本次连接已由对端结束，且未建立可用会话；撤销抑制并清理本次连接。
  expected 使用连接/会话的外部结果，回调、标记及队列清理因果仅放 source_evidence。
- **正例（当前只有骨架）**：若只有上述内部源码，而阈值、工具、连接结束的外部表现或会话查询未核实，
  保留“握手未继续时超时结束连接”的候选目标及这些缺口，标 unknown；若明确仅缺新增设施则标
  needs_instrumentation。不能把本示例照抄为 ready，也不把“消失或关闭”当作未经确认的二选一预期。

### 成对示例：认证交互不等于内部终态可观察

- **反例（真实问题表述）**：步骤“主机Connect，目标响应AUTHREQ后AuthSend/AuthReceive”；预期“主机继续认证而非直接建立会话”。步骤2“主机依次Negotiate、Challenge、Reply、Success1、Success2”；预期“认证成功：目标端最终进入SUCCESS2终态并释放本次认证资源，认证完成”。未说明真实控制能力、收发方向和每项观察，不能据此认定可执行黑盒；这些名称本身不是错误，也不是完整协议事实。
- **条件化正例**：若现有主机入口自动完成认证，操作写实际连接动作，按本次会话关联的协议记录观察已核实的交互，并按真实完成响应及已核实的连接/设备查询判定可用。只有现有协议工具支持逐阶段控制/确认时，才列相应报文操作及中途“尚未可用”的检查；不能凭示例添加命令、阶段或时间窗。
- **判据拆分**：SUCCESS2若是线上消息则写实际收发事件；若是公开状态则写查询对象与字段；若仅是私有枚举则移入证据。成功结果不能证明资源释放，具备本次资源归属、基线及结束条件的观测设施才保留资源断言；否则明确该验证缺口。入口/协议依据未核实标unknown，仅缺新增控制/观测设施标needs_instrumentation，不把骨架标ready。

## 业务可实施性与 70% 交付目标

先遵循冻结的 analysis_scene.objective：product-behavior 交付产品行为；interface-contract 交付公开接口输入、调用顺序、状态、返回与资源契约。缺少 objective 的旧任务保持其冻结规则，不从源码名称推断或重新分类。风险场景（risk-method-v1）以及显式 interface-contract 目标不设产品黑盒与灰盒 70% 比例目标；执行准备度仍逐条如实填写。

按 task.target、task.focus 和单元 purpose 阅读入口、主干与跨文件流程。主干 owner 负责把其他单元的必要挂接点、输入/输出及状态关系交代清楚；每个 worker 负责自己的真实边界和与主干的关系。没有源码依据的跨单元关系保留 unresolved。产品入口或调用方在冻结范围外时记录已确认的内部/公开接口边界与缺口，不把内部函数包装成产品操作，不猜入口，不越界读取。

改标签、移入附录或将白盒改名 note 凑比例。所有保留的正式与辅助用例均计入分母。
