# C/C++ 业务语义取证

仅补充当前场景的语言取证方法；职责、用例组织和准备度遵循本任务冻结的共同生成与场景规则。以下线索按当前候选的具体疑点使用，不要求逐项扫描。

- **入口支持性。** `extern`、非 `static`、可链接或跨文件调用只说明实现可调用。通过受支持接口契约、公开头文件及其使用约定、真实受支持调用方核实入口、参数和返回边界。已确认的公开 API 可直接测试，不必再追到 CLI；私有 helper 和测试桩不能冒充产品入口。
- **状态的业务作用。** 对影响当前场景的结构体字段、位标志及持久状态，结合设置、清除和后续读取位置解释其所属业务对象，以及它改变的响应、功能选择或后续操作。操作自然产生的状态不写成人工赋值。回调、宏或间接调用须按真实目标和求值关系核实，不凭名称推断作用。
- **批量对象范围。** 从容器成员来源、筛选条件和逐对象处理结果判断哪些对象受影响；一次循环不证明覆盖全系统，部分失败也不自动等于全部失败。仅保留影响验证目标的对象差异和顺序。
- **停止与释放边界。** 指针置空、句柄失效或字段重置不单独证明任务停止、资源释放。按直接所有者及释放、取消实现区分停止接收新工作、排空在途工作和完成释放。再次操作成功只能证明该次操作结果；资源断言需要其自身可用的观察依据。
- **受理与完成。** 区分函数受理返回、异步回调结果和最终对外响应；结合该路径的状态、错误传播和已有副作用解释失败后的重试与恢复。返回成功不能替代尚未发生的完成事件，异常结果也不自动构成缺陷。

复用已读证据，只为影响当前触发或判定的缺口补读冻结范围内的绑定、状态消费者或直接依赖。已能说明业务条件和结果时停止扩读，不按字段全仓追踪。源码证明当前行为，正确预期另核对需求、设计或公开契约；不足时保留具体缺口，不猜操作、设施、时限或外部结果。
