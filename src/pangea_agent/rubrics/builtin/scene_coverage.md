# 覆盖率分析职责

先读coverage_match_summary、coverage_diagnostics和coverage_gaps，核实来源、测量批次、版本、路径及函数/行/分支粒度，再理解对象模块主干结构化业务流程和缺口调用链。
来源中的合成、模拟、示例、版本未知等限制必须保留到每项结论；位置唯一匹配只确认定位。合成零覆盖提示可用于演示分析与补测设计，不得写成确认未执行或真实覆盖缺口。冻结范围没有调用者不证明测试套件未执行，未提供调用者或测试记录时明确待确认。
只围绕相关真实缺口深入补测，不变成全模块风险或全分支扫描。主干理解和流程图用于定位缺口，不形成普通基础功能用例的交付义务；正常操作只作为缺口用例的必要前置或恢复，不拆成独立补测，除非证据表明正常路径本身存在真实未覆盖目标。有效无新缺口允许零新增用例。
逐个缺口先评估来源适用性，再从精确目标反向追到冻结范围内的产品/公开接口入口及必要条件，说明已有普通操作为何不足、拟补用例新增什么参数、状态、顺序或故障条件。将这条依据写在现有用例说明或summary中，不新增记录schema。有业务情形及可论证触发方案即可保留候选设计；已有入口、设施和观测方式均核实才标ready，缺设施标needs_instrumentation，入口或条件尚不明标unknown或记note，并写明具体缺口；只有纯内部推演、无法建立外部业务情形时才仅记note。不能因暂缺设施丢弃真实故障设计，也不能只凭coverage_refs存在便认定命中。
缺口新增/实质补充用例使用purpose=coverage和真实coverage_refs；复用已有branch用例保留purpose。每个相关缺口在summary说明新增、补充、复用、不可达依据或具体执行条件缺口。跨单元缺口按规划的owner汇总处置，关联必要上下文，不让各单元重复生成主成功场景或互相假设对方负责。
路径重叠不证明触发；沿入口核实触发条件、外部判据、故障注入、清理和再次操作。需要新增桩点标needs_instrumentation，不能把调用私有函数当黑盒测试。
按 scene_common_generation 提炼缺口对应的业务情形和验证目标，缺口数、未覆盖 if/helper 数与用例数不要求一对一。同一业务用例可关联多个已核实能触发的真实缺口；独立故障条件、关键交错或契约差异仍要保留，不因最终结果相同合并。尚未核实实际触发方式时保留具体执行缺口，不制造置变量或逐函数检查用例。
需求、设计、历史缺陷和方法论用于解释预期与缺口测试价值；无关历史问题不扩展对象。不存在正式风险分析责任，不建风险账本，不强求risk_refs。
无数据、查询失败、版本未知、全部不匹配与有效无新缺口必须区分。确定为其他版本的数据只作参考，不计为当前有效缺口；版本未知明确限制。不同批次或计数冲突分来源解释，不取最后一条。
函数零执行与分支某一侧零计数是不同目标：函数count>0不排除内部某分支侧为0，也不证明拟定用例能触发该侧；行数据不能证明某个条件分支的覆盖。不能按标题、成功结果或函数count>0机械删除用例，同标题不同参数可能恰是缺口必要条件；真实未覆盖正常路径也可补测。无分母不计算覆盖率，无新缺口可交付流程及有依据的零新增结论。
Reviewer双向核查：每个case是否由具体适用gap支持、步骤新增的条件是否足以触发精确目标；每个相关gap是否有可核实的新增、补充、复用或执行缺口说明。排除仅复述已覆盖主干、把前置/恢复拆成独立用例、仅挂真实ID却没有触发条件的泛基础case；通过现有finding/定向修正由原worker用supersedes指向原record_id修正原记录，保留有效内容，不仅追加一条好用例而留下错误用例。用例关联不是已执行、不是覆盖率提升。不以缺口必须全部生成新用例或风险为空作为返修理由，不增加完整复核轮次。
Reviewer逐项对照来源限制与正文结论，不能仅凭报告开头有免责声明就接受正文中的实测断言。没有证据支持的执行、版本或可达性结论交回原worker定向修正，仍无法确认的结论保留UNRESOLVED。源码推导出的附加边界不自动成为实测Coverage缺口，按实际目的分类，不补造coverage_refs。
