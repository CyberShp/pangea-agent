# Lua 业务语义取证

仅补充当前场景的语言取证方法；职责、用例组织和准备度遵循本任务冻结的共同生成与场景规则。以下线索按当前候选的具体疑点使用，不要求逐项扫描。

- **入口支持性。** module 返回 table、导出函数或注册 handler 只说明实现可调用。核实适用的消息或服务绑定、参数来源及受支持调用契约，区分内部回调、测试 mock 和生产入口。已确认的公开 Lua API 可直接测试，不必强找 CLI；可 `require` 不证明测试人员拥有产品操作入口。
- **状态的业务作用。** 对影响当前场景的 table 字段、闭包 upvalue、缓存和注册表，结合设置、清除及后续读取位置解释所属业务对象，以及它改变的响应、功能或下一次操作。自然形成的状态不改写成人工置位；按 `:` 的 self 绑定、真假值、多返回值及实际元方法核实条件，不能套用 C 的返回值约定。
- **批量对象范围。** 核实集合成员来源、筛选条件和逐对象结果，不从变量名或一次遍历推断全系统对象；`pairs` 不保证处理顺序。仅保留影响验证目标的对象差异，不把每次内部调用拆成一个测试步骤。
- **停止与释放边界。** 普通 table 字段置 `nil` 只移除该引用，触发元方法时另核实其副作用；不能由此认定其他持有者、定时调度或已运行协程已结束。区分取消后续调度、停止当前处理和释放资源；GC 不能单独证明释放时机或内存回落。
- **受理与完成。** 区分异步启动返回、协程或消息完成及最终 RPC 响应。`pcall` 成功只表示调用未抛出错误，还需解释被调函数的业务返回；捕获异常不自动撤销已发生的副作用。结合实际完成契约说明失败后的状态与恢复。

复用已读证据，只为影响当前触发或判定的缺口补读冻结范围内的绑定、状态消费者或直接依赖。已能说明业务条件和结果时停止扩读，不逐字段全仓追踪。源码证明当前行为，正确预期另核对需求、设计或公开契约；不足时保留具体缺口，不猜操作、设施、时限或外部结果。
