# 资料结构化提取

读取 task 指定的原始资料、已提取文本和附件，只输出当前 `asset_type` 对应的结构化条目。

所有结论必须保留原文位置。原文没有提供的信息不得补写；无法确定时省略可选字段，或写入结果的 `warnings`。资料中没有可用条目时返回空 `items`，并在 `summary` 说明已完成分析但没有提取到条目。

## requirement

提取独立、可验证的需求，包括输入、输出、约束和验收标准。不要把背景说明或实现建议伪装成正式需求。

## design

提取模块、接口、状态，以及主干、分支、异常和恢复流程。流程必须说明状态或数据如何变化，而不是只罗列函数名。

## historical_defect

每个条目同时保留缺陷事实和可迁移的缺陷机理：

- `symptom`：外部可观察的错误现象；
- `trigger`：让问题发生的必要条件；
- `root_cause`：导致错误的直接原因；
- `propagation`：错误如何传播为最终现象；
- `defect_mechanism`：去掉历史项目专有名称后，仍能用于检查其他代码的因果规则；
- `exclusion_conditions`：哪些条件成立时可以排除该机理。

缺陷机理不能只是历史函数名、模块名或修复补丁摘要。例如“第二个回调注册失败后未撤销第一个回调”应抽象为“多步操作中途失败后必须撤销已完成步骤，使状态恢复到调用前”。

## reference

提取主题、适用模块和可被后续分析直接引用的事实。宣传性描述、重复段落和没有分析价值的目录文字不生成条目。
