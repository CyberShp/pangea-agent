# Lua 风险检查方法（risk-method-v1）

本文件给出 Lua 各镜头的检查程序。交付、账本、判据和记录格式以冻结的 scene_risk.md 为准。

## Lua 语义纪律

- 只有 nil 和 false 为假；0 和空字符串为真。`a and b or c` 在 b 为 false 或 nil 时返回 c。
- 区分两种错误约定：抛出（error、assert）与返回 `nil, err`。按调用点的实际约定追踪。
- 数字：Lua 5.3 起区分整数与浮点；`//`、`math.tointeger`、`string.format("%d", x)` 对非整数的行为按目标版本判断；目标版本未冻结时不下确定结论。
- 字符串与表的下标从 1 开始，string.sub 等接受负下标；`#t` 在有空洞的表上没有确定结果；pairs 的遍历顺序不确定。

## 镜头一：异常路径（error_path）

枚举：已修改状态（表字段、模块级变量、注册表、外部资源）之后可能抛错或提前返回的位置。

逐个回答：
1. 出错前已完成的修改；出错后是否回滚。
2. 调用方用 pcall/xpcall 包裹还是检查第二返回值；两种约定混用时，错误是否被吞掉或被当作成功。
3. 错误对象的类型（字符串或表）是否被当成字符串拼接或比较。
4. 远程调用（例如 skynet.call）失败后的传播和状态。
5. 下一次调用是否会读到残留状态。

## 镜头二：资源生命周期（resource_lifecycle）

资源包括文件句柄、socket、定时器、订阅和回调注册、fork 出的协程、模块级缓存表。

1. 每个获取点沿正常路径和每条错误路径（包括被 pcall 捕获之后）走到释放；错误路径上是否关闭。
2. 定时器和回调注册在对象销毁后是否注销；晚到的回调是否作用在已销毁的对象上。
3. 模块级缓存是否有上限或淘汰；按请求增长的表是否会无限增长。
4. __gc 和 __close 的执行时机不可依赖；需要确定时机的释放不能只靠它们。

## 镜头三：边界值（boundary）

1. 下标：1 基、负下标、`string.sub(s, i, j)` 越界时的结果、`#t` 用在有空洞的表上。
2. 协议字段和配置的长度上限与数值范围；tonumber 返回 nil 时的处理。
3. 整数与浮点：除法、取整、按目标版本的整数回绕。
4. 遍历一张表的同时修改它。

excluded 的 reasoning 写出代入极值后的结果。

## 镜头四：并发与时序（concurrency）

协程和服务模型中，交错发生在 yield 点（例如 skynet.call、skynet.sleep、skynet.wait、阻塞 I/O 的封装）。

1. 列出跨 yield 使用的状态：yield 之前读取、yield 之后继续使用的模块级变量、表字段和对象引用。
2. 写出具体交错：协程 A 在 yield 点挂起，协程 B 修改了什么，A 恢复后基于旧状态做了什么。
3. 消息处理是否可重入；同一服务内对请求顺序的假设是否成立；超时之后晚到的响应如何处理。

写不出具体交错的不算假设；调度模型无法从冻结证据确定时，结论为 unresolved。

## 镜头五：不可信输入（untrusted_input）

1. 解码后的字段可能为 nil、类型不符（数字与字符串混用）、缺失、超长或嵌套过深。
2. 每个字段使用前是否检查类型和范围；校验失败时是否被当作默认值继续。
3. 构造反例输入：缺字段、错类型、空字符串、超长字符串、负数、非整数。

## 镜头六：契约差异（contract）

1. 正确预期来自冻结的需求、设计和接口描述（IDL、接口文档）。
2. 逐个对外接口核对：参数、返回约定、错误码、同步或异步语义。
3. 区分实现违约（风险）、调用方违约（excluded，理由写 API 误用）、契约未规定（unresolved 或写入说明）。
