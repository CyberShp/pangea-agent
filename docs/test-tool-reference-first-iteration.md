# 第一轮：把已选工具资料变成有依据的操作

1. 新建 Run 时分别选择被测功能源码和测试工具参考文件/目录；查看展开后的文件清单再开始。工具不变成新的被测模块，也不要求先撰写完整工具说明。
2. 生成用例缺少入口、参数、观测或恢复办法时，原分析人员按需查阅已冻结的工具源码和说明。保存一份可共用的操作 note，说明真实命令模板、参数填法、执行位置、版本前提、自动行为、外部观测和清理/恢复，并附源码位置。
3. 先保存 note，取返回的 record_id；用例用现有顶层 `relates_to: [{"unit_id":"U1","record_id":"真实ID"}]` 关联。每例仍保留具体对象、参数值、动作和对应预期；详情与报告可查看关联说明。没有对应记录的引用保持待核实，不据此阻断 Run。
4. 工具只有 connect/query 时，不编造 pause、报文篡改或 reset。保留目标并说明还缺什么设施；自动认证不是人工逐消息操作，内部状态不是主要黑盒判据。
5. 原复核人员在已有轮次核实工具能力与操作依据。没有新增 Agent、强制语义门禁、复核轮次或工具执行。旧 Run 的冻结材料和规则不追溯更新。

## 本轮检查边界

合成小场景检查“冻结参考 → 读取 → 保存操作 note → case 显式关联 → 报告呈现”，覆盖同名主责隔离、缺失能力及旧 Run 冻结保持。它只证明输入与展示链路，不代表模型已能正确理解工具，也不是命令或真实设备验收。真实 provider 的后续验收应检查实际生成步骤及来源，并另行授权设备执行。
