# Coverage补测与黑盒判据优化

## 问题与范围

用户实例暴露两个语义问题：已覆盖普通路径被包装成缺口补测；删除函数名后仍用“进入SUCCESS2终态并释放认证资源”等私有实现结果作黑盒预期。现有规则已禁止泛化补测和中文化内部判据，因此不能将问题简化为缺少禁词。未核对实际Run冻结规则与执行轨迹前，不宣称已定位模型或装载的唯一原因。

本次仅强化新Run冻结规则、现有说明展示与确定性诊断，不增加Agent、完整复核轮次或强制schema字段；旧Run继续使用原冻结规则。

## 最小改动

- Coverage每个新增、补充或复用case用现有扩展字段`body.summary`对应真实`coverage_refs`，说明缺口粒度、来源/批次限制、外部条件及普通操作不足之处。复用保留purpose并解释现有步骤已满足哪些条件，允许零新增。全局summary不能替代逐case说明，真实ID与说明套话不能替代触发论证。
- 函数非零不排除内部零计数分支；真实未覆盖正常路径允许补测。旧0、新12及增量历史gap分来源解释，不自动抵消或冒充当前测量。
- 每个expected断言分别落实观察对象、方法及判定，不能夹带内部终态/清理。线上消息、公开字段、私有枚举按证据区分；自动交互不伪写成人工控制步骤。连接成功、再次连接成功不证明资源释放；缺少专门观察保留验证缺口。
- Reviewer在现有comparison中对照case实际步骤、summary、refs和源码，确定错误指向原记录/字段并交原worker定向修正，不只追加一条正确用例。

## 权限与误杀风险

Python只诊断可确定的字段形态、引用存在性及冻结输入事实；相关非致命异常仅warning，不拒写、不阻断、不重分类、不删改用例，不根据关键词、覆盖计数、标题或summary文案判断语义。字段缺失也不授权Python补造业务解释。真实引用不证明触发，说明非空不证明解释成立。

语义由原Agent/Reviewer判断。不能因SUCCESS2同名而删除协议消息或公开字段，不能因函数count>0删除未覆盖分支，不能要求复用case硬添无意义操作，不能因缺工具删除真实故障设计。需求/协议事实未明标unknown，明确仅缺新增设施标needs_instrumentation，不编造命令或必需阶段。

## 验收与证据边界

`verification/coverage_semantic_examples.py`与`verification/blackbox_semantic_examples.py`检查配对语料结构、来源描述、现有case结构以及规则装载/冻结。语义反例也应通过结构检查，避免偷渡内容门禁。自动通过不代表模型已生成正确结果。

人工或真实provider验收应向模型提供未标注候选和对应证据，再检查：真实gap+普通路径假关联、逐case缺说明/套话、多批次限制、零新增与复用、函数正计数内零分支、认证混合预期、自动协议交互、合法消息/公开状态、连接成功替证释放。Reviewer须给字段级反证并修原case。记录冻结版本及产物；未执行真实模型验收时保持待验证，不以fixture标签或规则文本命中冒充结果。
