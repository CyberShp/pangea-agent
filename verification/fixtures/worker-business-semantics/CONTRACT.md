# 合成打印队列：冻结接口与测试环境

这是从零编写的教学夹具，不含任何实际用户业务、用例或源码。C 与 Lua 实现具有相同业务契约，分别交给模型，不把另一语言或 `oracle.json` 作为输入。

## 分析任务

目标为打印任务的取消、进度订阅和失败处理，场景为分支分析，目标类型为 product-behavior。分析范围仅为本目录中选定的一份源码及本文。交付该范围有意义的用例和具体证据缺口，未提供实际 Coverage 数据。源码当前行为与本文冲突时分别说明，不假定实现就是正确预期。

## 已有环境

测试台已提供 `queue-demo`：C 或 Lua 版本均按参数顺序在同一个新进程执行多条命令，每条命令作为一个完整参数传入。进程间队列独立。命令中的整数均使用十进制。本夹具允许任务编号 1–4、组名为一个 ASCII 字母、页数 1–3；超出此域不是本轮分析目标。

例如 `queue-demo "add 1 A 2" "query 1" "step" "query 1"`。实际可执行文件路径由测试台配置提供，不能从这里推测产品命令。

`step` 是测试台已有的单步调度能力；一个命令完成一次完整调度，每个未结束任务最多打印一页。测试期间没有后台自动调度，不使用睡眠或假想毫秒窗口。没有提供内存写入、直接调用实现函数或注入任意设备返回值的能力。

## 支持的命令和独立业务要求

| 命令 | 要求与公开响应 |
| --- | --- |
| `add ID GROUP PAGES` | 创建不存在的任务，输出 `CREATED`；任务为 queued，printed=0，自动启用进度订阅。 |
| `query ID` | 输出 `STATE printed=N events=M`。STATE 为 queued/running/done/cancelled/failed；printed 是本任务实际已打印页数；events 是本次订阅累计收到的进度通知数。 |
| `step` | 输出 `ADVANCED`。正常任务打印一页并发送一次进度通知（有订阅时）；最后一页完成后状态 done。 |
| `unwatch ID` | 输出 `UNWATCHED`，仅停止该任务后续进度通知，保留已有通知计数；任务仍应继续打印，可用 query 查看结果。 |
| `cancel GROUP` | 对该组 queued/running 任务受理取消，输出 `ACCEPTED N`；尚不代表任务已取消。下一次 step 将这些任务置为 cancelled，且不再增加打印页数。其他组、已结束任务不受影响。 |
| `fail-next ID` | 已有测试台故障注入：使指定任务下一次实际打印尝试失败，输出 `ARMED`；该尝试不增加打印页数或进度通知，状态 failed。若任务先被取消，不能据此声称发生过打印失败。 |
| `reset` | 清除本进程全部任务和注入设置，输出 `RESET`。测试结束可 reset，或退出此隔离进程。 |

`query` 的状态、页数及通知计数是支持的外部观察；实现中的取消标记、订阅句柄或内部返回值不是该查询的额外字段。

## 尚未提供的能力与资料

驱动可能主动报告“介质脱落”，业务要求是相关未结束任务转为 failed，保留已打印页数。但测试台没有介质脱落注入或真实设备操作能力。不能把 `fail-next` 等同于驱动主动上报。

源码还包含一个维护入口，未提供其调用方、对外绑定、允许模式或业务要求。函数被链接/模块导出只证明代码可见。本轮不能越界寻找缺失资料，也不要求凭名称猜测其业务用途。
